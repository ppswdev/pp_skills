# pp-ads-check 使用指南

`pp-ads-check` 是面向 Google AdMob 移动广告接入的合规审查技能，也可以对 Web AdSense 做政策对照。适合在**接入广告后、提审上架前、收到政策警告后**使用。

## 包内容

```
pp-ads-check/
├── SKILL.md                        # 审查流程主入口
├── README.md
├── CONFIG.md
├── 使用指南.md
├── scripts/
│   └── ads_audit.sh                # 只读静态扫描脚本
└── references/
    ├── platform-config-baseline.md # 平台配置基线
    ├── ad-call-chain.md            # 调用链与生命周期
    ├── admob-policy-checklist.md   # 政策合规清单
    └── invalid-traffic-device.md   # 无效流量与机型分析
```

## 快速开始

### 1. 上架前全面审查

```text
用 pp-ads-check 审查这个 Flutter 项目的 AdMob 接入，下周上架
```

执行动作：运行静态扫描 → 识别平台和广告格式 → 配置检查 → 调用链分析 → 政策核对 → 机型/无效流量分析 → 输出 P0/P1/P2 报告。

### 2. 针对单个广告格式

```text
帮我检查插屏广告的展示时机是否违规
检查激励广告的奖励发放逻辑能不能被刷
开屏广告这样写会不会被判定遮挡其他广告
```

会还原该格式的加载 → 就绪检查 → 展示 → 回调 → 销毁时序，逐条给出证据。

### 3. 隐私合规专项

```text
App 要上欧洲区，UMP 和同意流程帮我过一遍
儿童受众 App 的 COPPA 标记都配对了吗
iOS 这边 ATT 弹窗时机和文案有没有问题
```

### 4. 风险应急

```text
AdMob 政策中心提示无效流量，帮我排查并给出申诉前自查清单
广告点击率突然异常升高，帮我列出下钻分析步骤
```

## 如何运行扫描脚本

脚本只读，不改任何文件，依赖系统自带的 bash/find/grep：

```bash
bash scripts/ads_audit.sh /path/to/your/project
```

输出包括：项目类型识别、SDK 版本线索、平台配置项、初始化位置、UMP/ATT/COPPA/TFUA/CCPA 标记、测试设备与 demo ID、所有 `ca-app-pub-*` ID、各广告格式调用特征、WebView 高风险行为、app-ads.txt 线索。

脚本告警是**线索**不是结论——demo ID 出现在 debug 代码里是正常的，是否进入发布版本需要人工结合构建配置确认。

## 支持平台

| 平台 | 技术栈 |
| --- | --- |
| iOS | Swift / Objective-C，CocoaPods 或 SPM |
| Android | Kotlin / Java，Gradle |
| 跨端 | Flutter（`google_mobile_ads`），两端原生配置仍需分别检查 |
| Web | AdSense 政策对照 |

## 审查报告包含什么

1. **问题清单**：级别（P0/P1/P2）、类别、问题、证据（文件#行号）、政策依据、修复建议。
2. **需后台确认清单**：AdMob 广告位设置、频次上限、政策中心状态、Play/App Store 隐私标签、app-ads.txt 线上可访问性。
3. **需运行时验证清单**：同意弹窗四条分支（同意/拒绝/未达年龄/撤回）、多机型误触、中介填充。
4. **核对过的官方文档链接与日期**。

## 注意事项

- 技能全程**只读**，不会改动你的广告代码。
- Google 政策和 SDK API 更新频繁，关键结论会联网核对 developers.google.com / support.google.com 后给出。
- demo 广告位 ID 只能用于开发测试；正式包里出现 demo ID 是 P0 红线。
- 不要自行点击正式广告"测试效果"，真机联调请注册测试设备。
- 其他广告网络（Meta、Unity Ads、AppLovin 等）的自有政策不在审查范围内，中介场景只检查对接配置。
