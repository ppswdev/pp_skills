# 无效流量、机型与测试设备检测分析

本文件是 pp-ads-check Step 4 的工作基线，分三部分：开发期测试防护（代码可证）、机型与场景适配（代码+运行时）、无效流量数据分析（需后台确认）。

官方依据：

- 启用测试广告：https://developers.google.com/admob/ios/test-ads、`/android/test-ads`、`/flutter/test-ads`
- 无效流量说明：https://support.google.com/admob（搜索 invalid traffic / 无效流量）
- 广告投放限制说明：AdMob 帮助中心"广告投放限制"主题

## 1. 无效流量的类型

| 类型 | 典型表现 | 代码侧排查点 |
| --- | --- | --- |
| 误触（accidental clicks） | 点击率高、点击后秒回、转化为零 | 广告与可点控件距离、Banner 位置、开屏关闭按钮大小 |
| 自行点击（self clicks） | 开发者/团队 IP/设备高频点击 | 测试设备注册、发布前走查、团队规范 |
| 诱导点击（incentivized clicks） | 文案/动画引导点广告 | 搜索"支持我们/点击广告/click ad"文案与箭头素材 |
| 自动点击/注入（click injection） | 点击间隔高度规律、无曝光前置 | `performClick`、无障碍服务、悬浮窗、脚本引擎、第三方 SDK 可疑调用 |
| 点击泛滥（click flooding） | 点击量远高于展示量、CTR 畸高 | 广告 SDK 初始化次数、第三方归因/增长 SDK |
| 机器人/群控（device farms） | 机型/分辨率/OS 版本高度集中，新设备占比异常 | 流量来源、分发渠道、后台数据细分 |
| 展示作弊 | 不可见广告产生展示、堆叠像素广告 | 后台静默 load/show、零尺寸视图、视图遮挡关系 |
| VPN/代理流量 | IP 地理与语言/商店地区不符 | 异常获客渠道、激励买量 |

## 2. 开发期测试防护（P0 红线）

### 2.1 两种合法测试方式

1. **Google demo 广告位 ID**：与账号无关，点击不产生计费；各格式 ID 以官方测试广告文档为准（脚本内置常见 demo ID 列表，版本更新后需核对）。
2. **真机注册为测试设备**：使用自己的正式广告位 ID 但设备被标记为测试设备。
   - Android 模拟器自动是测试设备；真机通过 `RequestConfiguration.setTestDeviceIds` 注册，设备 ID 可在 Logcat 首启日志找到。
   - iOS 模拟器在测试设备列表中加入 `GADSimulatorID`（Swift 为 `GADSimulatorID`）；真机通过 `requestConfiguration.testDeviceIdentifiers` 注册，ID 来自控制台日志。
   - Flutter 两端机制同上，统一在 `RequestConfiguration(testDeviceIds: [...])` 设置。

### 2.2 发布检查

- release 构建中**禁止**出现 demo ID；环境切换必须集中（单一配置层 + 构建变体）。
- 测试设备注册代码用 DEBUG 条件隔离，避免团队成员直接点正式广告。
- 禁止"上线后自己点几下看看能不能出广告"——这是最常见的误封原因。
- QA/外包测试机统一注册；远程演示、录屏、自动化 UI 测试期间屏蔽正式广告或使用 demo ID。

## 3. 代码侧高风险模式检测

| 风险 | 检测方法 | 级别 |
| --- | --- | --- |
| 自动触发点击 | 搜索 `performClick`、`callOnClick`、无障碍派发、合成 `MotionEvent`/触控注入与广告视图的组合 | P0 |
| 加载即展示、展示即再加载 | 审查 load 回调内无条件 show、show 失败立即重试的链路 | P1 |
| 不可见展示 | 广告 View 在 `alpha=0`、零尺寸、屏幕外、被遮挡、页面未 `onResume`/已进入后台时 load 或展示 | P0 |
| 自定义刷新 Banner | Timer/Handler/setInterval 周期性重新 load Banner | P0 |
| WebView 广告 | WKWebView/WebView 加载 googlesyndication、doubleclick、adsense 相关 URL/JS | P0 |
| 越权采集标识 | 直接读取 IDFA/GAID、序列号、MAC、Android ID 并上传；绕过 ATT/同意弹窗 | P0 |
| 篡改广告请求 | Hook、代理、修改 SDK 网络请求或使用非官方 SDK 分支 | P0 |
| 多 SDK 冲突 | 同一功能接多套广告/归因 SDK 重复加载、初始化竞态 | P1 |
| 错误重试风暴 | 失败回调无退避立即 reload，产生异常请求密度 | P1 |

> 模拟器/越狱 Root 检测本身不是政策要求；允许用于"切换测试 ID"等开发者逻辑，但**不得**把设备判定用于对不同用户/地区展示不同合规行为（如检测到欧洲设备才弹同意）。同意流程必须按地区法规对所有适用用户生效。

## 4. 机型与场景适配（误触与展示质量）

### 4.1 布局审查清单

- **iOS**：安全区（safe area）、灵动岛/刘海、底部 Home Indicator 区域、iPad regular 尺寸、横竖屏、Stage Manager/分屏。
- **Android**：手势导航条、挖孔/曲面屏、折叠屏展开-合拢、平板、分屏、高字体缩放（dp/sp）。
- **通用**：Banner 使用自适应尺寸并在旋转/折叠后重算；广告与原生按钮间距满足最小防误触；深色模式下广告标识仍可见。
- **开屏**：各机型启动图比例下关闭按钮位置不被裁切。
- **原生广告**：列表复用（cell/ViewHolder）中广告视图状态不错位、不串内容。

### 4.2 运行时验证方法

- 至少覆盖：小屏旧机型（如 iPhone SE/小尺寸 Android）、主流大屏、平板；一个高 OS 版本 + 一个最低支持版本。
- 用录屏慢放检查：插屏出现时机、误触距离、关闭按钮热区、奖励发放流程。
- 弱网/无填充（NO_FILL）场景：确认不崩溃、不白屏阻塞、重试有退避。
- 同意路径四条分支全测：同意、拒绝、未达年龄、撤回后重启。

## 5. 后台数据异常分析（需用户提供 AdMob 后台数据）

> 这部分代码无法取证，输出到报告"需后台确认"，并指导用户按以下维度自查。

### 5.1 核心指标与基线信号

| 信号 | 异常表现 | 建议动作 |
| --- | --- | --- |
| CTR（点击率） | 相对历史基线突增、远高于同类 App 均值 | 立即按广告位、机型、地区、渠道下钻 |
| 展示量 | 无版本更新/买量动作下陡增 | 排查重复加载、后台展示、第三方刷量 |
| 匹配率/填充 | 骤降 | 检查适配器版本、同意状态、广告位配置、eCPM floor |
| eCPM | 异常波动伴随无效流量警告 | 下钻流量来源 |
| 政策中心通知 | invalid traffic、广告投放限制、展示受限 | 进入第 6 节 SOP |

### 5.2 下钻维度

1. **广告位/格式**：异常集中在哪个广告位（往往是展示位置或时序问题）。
2. **机型与 OS 版本**：点击是否集中在少数机型/分辨率/旧系统（群控或误触布局问题）。
3. **国家/地区与语言**：IP 地区与设备语言、商店地区是否矛盾（VPN/代理农场特征）。
4. **App 版本**：异常是否从某版本开始（定位回归问题）。
5. **流量渠道**：自然量 vs 买量/预装/激励渠道；某渠道异常立即暂停。
6. **时间分布**：点击是否机器节律（整点爆发、间隔恒定、无夜间低谷）。
7. **设备标识**：广告 ID 归零率、重置率异常高；同一会话多 ID。
8. **点击-展示关系**：点击前是否有足够展示时长（秒退点击是误触/作弊特征）。

### 5.3 常见根因对照

| 后台现象 | 最可能根因 |
| --- | --- |
| 某机型 CTR 异常高 | 该机型布局误触（Banner 盖住按钮/手势条） |
| 新版本上线后展示量翻倍 | 重复加载、页面重建重复 load、前后台监听重复注册 |
| 某地区填充骤降 | UMP 同意配置错误、中介伙伴名单缺失、地区屏蔽设置 |
| 新账号直接被限投 | 风控观察期 + 开发者自行点击/小范围真实用户高频测试 |
| 激励广告奖励投诉 | 未用 SSV、奖励回调被本地篡改/断网时序问题 |

## 6. 收到无效流量处置后的应急 SOP

1. 暂停可疑广告位或整个 AdMob 投放（保留账号，不要抢在风控前继续灌量）。
2. 暂停所有可疑买量/换量/预装渠道。
3. 用本技能四步流程审查代码，重点：自动行为、不可见展示、误触布局、测试设备。
4. 后台按 5.2 维度截图取证，锁定影响范围与起始时间。
5. 发版修复 + 内部测试规范（demo ID/测试设备/上线 checklist）。
6. 通过政策中心申诉，写明：根因、证据、修复版本与时间、预防机制。
7. 解封/恢复观察期内不做激进变现改动，持续监控 CTR 与政策中心。
