# 产品需求挖掘 Skills 清单

> 更新时间：2026-05-14  
> 适用对象：产品经理、独立开发者、创业者、AI Native 小团队、增长前置研究人员  
> 目标：只整理服务于「找机会、找需求、找赛道、判断可行性」的 Skills，不覆盖产品设计、开发实现、投放增长、销售变现等后续环节。

## 一句话结论

产品需求挖掘类 Skills 的核心不是“生成更多点子”，而是帮助团队稳定完成这条链路：

**扫描机会 -> 捕捉用户痛点 -> 验证需求强度 -> 判断赛道空间 -> 评估可行性 -> 收敛 MVP 机会**

建议优先建设 6 个基础 Skill：

| 优先级 | Skill | 建议目录 | 主要用途 |
| --- | --- | --- | --- |
| P0 | `opportunity-signal-scanner` | `skills/opportunity/` | 从趋势、社区、搜索、竞品、政策、技术变化中发现机会信号 |
| P0 | `pain-point-miner` | `skills/research/` | 从评论、工单、访谈、论坛、社媒中提炼真实痛点 |
| P0 | `jtbd-demand-synthesizer` | `skills/research/` | 把用户表达转成 JTBD、触发场景、替代方案和成功标准 |
| P0 | `market-segment-mapper` | `skills/opportunity/` | 拆分用户群、使用场景、细分赛道和切入点 |
| P0 | `opportunity-scorecard` | `skills/strategy/` | 用统一维度给机会打分，避免只凭感觉选题 |
| P0 | `mvp-feasibility-analyzer` | `skills/product/` | 判断 MVP 是否能低成本验证，输出验证路径和风险 |

## 需求挖掘 Skill 分类

| 分类 | 适合目录 | 解决的问题 | 典型产出 |
| --- | --- | --- | --- |
| 机会信号扫描 | `skills/opportunity/` | 从外部变化中发现可能的新需求 | 趋势信号、机会假设、证据链接、观察列表 |
| 痛点与需求提炼 | `skills/research/` | 判断用户到底在抱怨什么、想完成什么任务 | 痛点主题、需求强度、JTBD、用户原话证据 |
| 赛道与细分市场 | `skills/opportunity/` | 判断哪个人群、场景、垂直领域更适合切入 | 市场地图、细分用户、切入点、避开领域 |
| 竞品与替代方案 | `skills/research/` | 理解用户现在如何解决问题、为什么不满意 | 竞品矩阵、替代路径、差异化机会 |
| 可行性分析 | `skills/strategy/` 或 `skills/product/` | 判断能不能做、值不值得做、怎么验证 | 可行性报告、风险清单、MVP 验证计划 |
| 机会优先级 | `skills/strategy/` | 在多个想法之间做取舍 | 机会评分、优先级排序、下一步行动 |

## 推荐 Skills 总表

说明：

- `P0`：需求挖掘最小闭环必备。
- `P1`：建议尽快补齐，适合系统化选题和持续找机会。
- `P2`：按行业、团队阶段、数据条件选择建设。
- `建议自建`：适合用本仓库的 `skills/` 目录沉淀为长期资产。
- `平台型能力`：依赖浏览器、搜索、数据表格或第三方工具，不一定要放入通用 Skill。

| 优先级 | Skill 名称 | 类型 | 建议目录 | 触发场景 | 主要产出 |
| --- | --- | --- | --- | --- | --- |
| P0 | `opportunity-signal-scanner` | 建议自建 | `skills/opportunity/` | 想系统发现新产品机会、趋势机会、AI 应用机会时 | 机会信号、来源证据、初步假设、观察优先级 |
| P0 | `pain-point-miner` | 建议自建 | `skills/research/` | 有评论、社群聊天、工单、访谈、Reddit、Twitter/X 内容需要提炼时 | 痛点主题、用户原话、频率、严重度、付费暗示 |
| P0 | `jtbd-demand-synthesizer` | 建议自建 | `skills/research/` | 需要把用户反馈转成任务、动机、阻力和成功标准时 | JTBD、触发场景、当前替代方案、需求强度 |
| P0 | `market-segment-mapper` | 建议自建 | `skills/opportunity/` | 需要判断目标用户、垂直场景、细分赛道如何拆分时 | 用户分层、场景分层、细分市场地图、切入顺序 |
| P0 | `competitor-alternative-scan` | 建议自建 | `skills/research/` | 需要研究竞品、替代方案、用户为什么换工具时 | 竞品矩阵、替代路径、差异化空位、不建议进入点 |
| P0 | `opportunity-scorecard` | 建议自建 | `skills/strategy/` | 手上有多个产品想法，需要排序和决策时 | 评分表、证据强弱、优先级、推荐行动 |
| P0 | `mvp-feasibility-analyzer` | 建议自建 | `skills/product/` | 需要判断一个需求能否用 MVP 快速验证时 | MVP 范围、验证实验、资源评估、关键风险 |
| P1 | `trend-to-product-idea-mapper` | 建议自建 | `skills/opportunity/` | 看到 AI、平台、政策、消费趋势变化，想转成产品机会时 | 趋势解释、受影响人群、产品假设、验证路径 |
| P1 | `search-intent-opportunity-miner` | 平台型能力 | `skills/opportunity/` | 需要从搜索关键词、长尾词、SEO 数据中发现需求时 | 搜索意图、关键词簇、需求主题、内容/产品机会 |
| P1 | `community-demand-researcher` | 平台型能力 | `skills/research/` | 需要研究 Reddit、Discord、Slack、论坛、微信群等社区讨论时 | 高频问题、情绪强度、用户群画像、机会摘录 |
| P1 | `review-mining-analyst` | 平台型能力 | `skills/research/` | 需要分析 App Store、G2、Product Hunt、Chrome Store、Amazon 评论时 | 用户不满点、期待功能、替代品缺陷、证据表 |
| P1 | `willingness-to-pay-detector` | 建议自建 | `skills/strategy/` | 需要判断需求是否有付费可能，而不只是“用户喜欢”时 | 付费信号、预算来源、购买角色、价格敏感点 |
| P1 | `tam-sam-som-estimator` | 建议自建 | `skills/strategy/` | 需要粗估赛道空间、可服务市场和早期可拿下市场时 | TAM/SAM/SOM 假设、计算口径、数据缺口 |
| P1 | `problem-solution-fit-checker` | 建议自建 | `skills/product/` | 想判断解决方案是否真的对准问题时 | 问题-方案匹配度、错配风险、待验证假设 |
| P1 | `user-interview-question-designer` | 建议自建 | `skills/research/` | 准备做用户访谈、需求验证、冷启动调研时 | 访谈提纲、追问问题、避免诱导的问题清单 |
| P1 | `landing-page-smoke-test-planner` | 建议自建 | `skills/product/` | 想用落地页、等待名单、广告小预算验证需求时 | Smoke test 方案、页面信息架构、验证指标 |
| P2 | `regulatory-and-policy-opportunity-scanner` | 建议自建 | `skills/opportunity/` | 面向合规、税务、医疗、教育、跨境、隐私等受政策影响领域时 | 政策变化、受影响人群、机会与合规风险 |
| P2 | `technology-capability-opportunity-mapper` | 建议自建 | `skills/opportunity/` | 新技术能力出现后，需要判断可产品化方向时 | 技术能力拆解、可替代流程、应用场景、落地门槛 |
| P2 | `workflow-automation-opportunity-finder` | 建议自建 | `skills/opportunity/` | 想在 B2B、专业服务、内部运营中找自动化机会时 | 工作流地图、低效环节、自动化机会、ROI 假设 |
| P2 | `niche-saas-idea-validator` | 建议自建 | `skills/strategy/` | 独立开发者想判断一个垂直 SaaS 点子是否值得做时 | 利基市场评估、竞品密度、获客难度、MVP 建议 |
| P2 | `idea-kill-criteria-designer` | 建议自建 | `skills/strategy/` | 团队容易恋战，需要提前定义放弃条件时 | 继续/暂停/放弃标准、验证期限、证据阈值 |

## 最小需求挖掘 Skill 组合

如果只想先搭一套最小可用的需求挖掘能力，建议按下面顺序建设：

| 顺序 | Skill | 为什么先做 |
| --- | --- | --- |
| 1 | `opportunity-signal-scanner` | 先建立稳定的机会输入源，而不是靠灵感选题 |
| 2 | `pain-point-miner` | 用用户原话和真实抱怨筛掉伪需求 |
| 3 | `jtbd-demand-synthesizer` | 把“想要某功能”还原成用户真正要完成的任务 |
| 4 | `market-segment-mapper` | 找到更小、更具体、更容易切入的用户和场景 |
| 5 | `competitor-alternative-scan` | 理解用户当前怎么解决，以及为什么现有方案不够好 |
| 6 | `opportunity-scorecard` | 用统一维度排序机会，减少拍脑袋决策 |
| 7 | `mvp-feasibility-analyzer` | 把机会收敛成能快速验证的 MVP 路径 |

## 机会评分建议维度

`opportunity-scorecard` 建议固定使用一套评分维度，方便不同想法之间横向比较：

| 维度 | 关注问题 | 高分信号 |
| --- | --- | --- |
| 痛点强度 | 用户是否频繁、明确、带情绪地表达问题 | 有大量真实原话、抱怨具体、影响收入/效率/风险 |
| 现有替代方案缺口 | 用户现在怎么解决，为什么不满意 | 现有方案贵、慢、复杂、需要拼工具、体验差 |
| 付费可能 | 谁会为它付钱，预算从哪里来 | 有明确预算、替代人工成本、已有付费竞品 |
| 市场可达性 | 早期能否触达目标用户 | 社区集中、关键词明确、渠道可测试、用户身份清晰 |
| 竞争压力 | 赛道是否拥挤，能否差异化 | 大厂不敏感、垂直场景明确、差异化切口清楚 |
| MVP 可验证性 | 能否用小范围实验验证 | 1-4 周内可做原型、可量化验证、依赖少 |
| 团队匹配度 | 团队是否有经验、渠道或技术优势 | 有领域理解、已有用户入口、技术能力适配 |
| 风险与约束 | 是否存在合规、平台、数据、供应链风险 | 风险可控、边界清楚、验证前不需重投入 |

建议输出格式：

| 机会 | 总分 | 最强证据 | 最大风险 | 推荐动作 |
| --- | --- | --- | --- | --- |
| 示例机会 A | 82/100 | 用户高频抱怨现有方案太复杂 | 获客渠道未验证 | 做 10 人访谈 + 等待名单 |

## 每个 Skill 建议包含的内容

为了便于 Codex、Claude Code、VS Code、Trae 复用，每个需求挖掘 Skill 的 `SKILL.md` 建议保持轻量、证据导向，并包含：

| 模块 | 内容建议 |
| --- | --- |
| `name` | 使用英文短横线命名，例如 `pain-point-miner` |
| `description` | 写清楚触发时机，例如“当用户要从评论、社区讨论、访谈或工单中挖掘需求和痛点时使用” |
| 输入类型 | 支持用户原话、网页摘录、评论 CSV、访谈记录、竞品链接、关键词列表等 |
| 工作步骤 | 以 4-7 步为宜，覆盖证据抽取、聚类、强度判断、机会假设和下一步验证 |
| 输出格式 | 固定输出表格、评分卡、假设列表、访谈问题、验证计划等 |
| 证据要求 | 明确哪些结论来自用户原话，哪些只是推断，哪些需要继续验证 |
| 质量标准 | 避免空泛点子，优先输出可验证、可比较、可行动的机会 |
| 示例调用 | 给 2-3 个真实用户说法，方便 agent 自动触发 |

大型行业资料、赛道地图、访谈模板、评分模型、样例报告，建议放入 Skill 内部的 `references/`，不要塞满 `SKILL.md`。

## 不纳入本清单的 Skills

以下能力虽然和产品成功有关，但不属于“只针对产品需求挖掘”的范围，建议放到其他清单：

| 不纳入类型 | 原因 | 建议目录 |
| --- | --- | --- |
| PRD 详细撰写、用户故事、验收标准 | 已进入需求定义和交付阶段 | `skills/product/` |
| 信息架构、交互流程、UI 设计、可用性评审 | 属于产品设计阶段 | `skills/design/` |
| 前端开发、后端开发、测试、部署 | 属于工程实现阶段 | `skills/engineering/` |
| SEO 内容生产、社媒分发、广告投放 | 属于增长获客阶段 | `skills/growth/` |
| 定价页、套餐设计、支付转化 | 属于变现阶段 | `skills/monetization/` |
| 客服 SOP、知识库、工单处理 | 属于支持与运营阶段 | `skills/support/` 或 `skills/operations/` |

## 建设建议

1. 先建设 `P0`，确保从“发现信号”到“判断是否值得做”能闭环。
2. 每个 Skill 都要要求输出证据，不要只输出观点。
3. 需求挖掘 Skill 应该区分“事实、用户原话、推断、待验证假设”。
4. 机会判断不要只看市场大不大，还要看早期用户是否可触达、MVP 是否可验证。
5. 如果某个 Skill 需要联网、浏览器、表格或第三方数据，主 Skill 只写方法论和输出格式，把工具依赖写成可选能力。
6. 不要把“找机会 + 写 PRD + 画界面 + 写代码”合成一个巨型 Skill；需求挖掘阶段的终点应该是清晰的机会判断和验证计划。
