# 新增技能维护流程

新增或修改 skill 时，必须同时更新源目录、角色映射、用法说明和项目级镜像目录。不要只把 `SKILL.md` 放进 `skills/` 就结束，否则项目同步时可能无法按角色启用。

## 标准流程

1. 在 `skills/<编号_分类>/<skill-name>/` 新增或修改 skill。
2. 确认 `SKILL.md` frontmatter 至少包含：
   - `name`
   - `description`
3. 在 `docs/02_skill-catalog/role-map.yml` 中补充该 skill：
   - `domain`
   - `roles`
4. 生成文档索引和具体用法页：

```bash
scripts/generate-docs-index.sh
```

5. 按角色同步到三个项目级技能入口：

```bash
scripts/sync-skills.sh --role 程序开发者
scripts/sync-skills.sh --role 本地化
scripts/sync-skills.sh --role 程序开发者 --role 本地化
```

6. 运行验证：

```bash
scripts/validate-skills.sh --role 程序开发者
```

## 目录规则

- 分类嵌套只放在 `skills/` 中。
- `.claude/skills/`、`.codex/skills/`、`.trae-cn/skills/` 必须保持扁平镜像。
- `skill-name` 必须全局唯一，因为同步脚本会把所选角色 skills 放到扁平入口目录。

## 角色规则

- `docs/02_skill-catalog/role-map.yml` 是项目级同步的数据源。
- 新增 skill 后必须配置 `roles`，否则不会进入任何角色同步结果。
- 一个 skill 可以属于多个角色，例如 `pp-tran` 同时属于本地化、程序开发者、独立开发者、运营增长。
- 日常不要用 `scripts/sync-skills.sh --all`，它只用于维护或调试。

## 文档规则

- `docs/03_skill-usage/<skill-name>.md` 是安装后的用户用法说明。
- 用法页中的自动区块由脚本维护：

```md
<!-- AUTO-GENERATED:START -->
...
<!-- AUTO-GENERATED:END -->
```

- 需要人工补充团队案例时，写在自动区块外，避免被生成脚本覆盖。

## 完成标准

新增或修改 skill 后，至少满足：

- `scripts/validate-skills.sh --role <目标角色>` 通过。
- `docs/03_skill-usage/<skill-name>.md` 存在。
- `docs/02_skill-catalog/技能总览.md` 能看到该 skill。
- 目标角色同步后，三个项目镜像目录中都能看到同名 skill：
  - `.claude/skills/<skill-name>/`
  - `.codex/skills/<skill-name>/`
  - `.trae-cn/skills/<skill-name>/`
