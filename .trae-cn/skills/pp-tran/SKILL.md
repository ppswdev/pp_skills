# pp-tran 国际化多语言自动翻译工具

`pp-tran` 是 `pp-translator` 的简称。两者指向同一个多语言翻译能力；在当前技能仓库中，正式技能名称使用 `pp-tran`。

## 目录结构

```
pp-tran/
├── SKILL.md
├── README.md
├── CONFIG.md
├── 使用指南.md
└── references/
    └── 国际化各个国家地区策略指南.md
```

`SKILL.md` 是主入口，保持任务流程和触发规则精简。国家和地区本地化策略等长内容放在 `references/` 中，仅在需要细分市场表达、文化适配或语言风格校验时读取。

## 功能描述

本工具用于自动进行国际化多语言翻译，**支持简体中文(zh-CN)和英文(en)双基准语言**，开发者只需维护其中一种语言，即可自动增量翻译到项目中的所有其他国家语言。翻译时严格遵循目标国家的语言文化习惯、行业标准用语和本地化策略，确保专业级翻译质量。

## 核心特性

✅ **双基准语言支持** - 支持以简体中文或英文作为翻译基准
✅ **智能增量翻译** - 只翻译新增或修改的内容，避免重复翻译
✅ **专业翻译质量** - 符合目标国家的文化习惯和行业术语
✅ **多格式支持** - Flutter .arb、iOS .strings、JSON、YAML
✅ **自动文件扫描** - 自动识别项目中的语言文件目录
✅ **差异对比** - 自动分析基准语言与目标语言的差异

## 翻译基准语言优先级

1. **自动检测**：优先扫描项目中存在的基准语言文件
2. **简体中文优先**：如果同时存在，默认以简体中文为基准
3. **支持手动指定**：用户可明确指定使用英文作为基准

## 使用方法

### 1. 自动检测模式（推荐）

直接说明需求，工具会自动扫描项目并识别基准语言：

```
"同步翻译多语言"
"生成其他语言版本"
"翻译国际化文件"
```

### 2. 指定基准语言

明确指定使用哪种语言作为翻译基准：

```
"按照简体中文进行生成"
"按照英文进行生成"
"以英语为基准翻译所有语言"
```

### 3. 自定义参数

| 参数     | 说明                 | 默认值                                                       |
| -------- | -------------------- | ------------------------------------------------------------ |
| 目录路径 | 指定语言文件所在目录 | 自动扫描：l10n、lib/l10n、src/locales、assets/l10n、\*.lproj |
| 基准语言 | zh-CN 或 en          | 自动检测，优先简体中文                                       |
| 目标语言 | 需要翻译的目标语言   | 除基准语言外的所有语言                                       |
| 翻译模式 | 增量/全量            | 增量翻译                                                     |
| 覆盖模式 | 是否覆盖已翻译内容   | 仅覆盖空值和新增内容                                         |

### 4. 选中内容增量翻译（最常用）

这是你日常开发中最常用的模式：**临时添加几个 key，选中后只翻译这部分内容**

#### 工作流程

1. 用户在基准语言文件中添加/修改了几个 key-value
2. 用户选中了这些新增或修改的内容
3. 自动识别这些 keys，只翻译它们到其他语言
4. **不影响**其他已翻译的内容

#### 触发方式（直接说就行）

```
"就翻译我选中的这几个"
"只翻译刚才新增的内容"
"翻译这几个key到其他语言"
"把我选的这几条同步到日文韩文"
"增量翻译，就这几个"
```

#### 特点

✅ **精确翻译**：只翻译指定的 keys，不会改动其他内容
✅ **速度快**：不需要扫描整个项目
✅ **无副作用**：不会覆盖或影响已翻译的内容
✅ **开发友好**：完美适配日常增量开发流程

### 5. 示例命令

```
"同步翻译，目录为 lib/l10n"
"按照英文进行生成，使用全量翻译"
"只翻译日文和韩文，以简体中文为基准"
"翻译 iOS .strings 文件"
"就翻译我刚才选中的这5条"
"只翻译新增的这几个key"
```

## 翻译质量控制标准

### 通用质量要求

1. ✅ **准确性**：专业术语必须准确，符合行业规范
2. ✅ **自然度**：符合目标语言的表达习惯，不是机翻腔
3. ✅ **文化适配**：符合目标国家的文化习惯
4. ✅ **长度控制**：UI 文本不宜过长，保持简洁
5. ✅ **一致性**：相同术语在整个项目中保持一致
6. ✅ **语境理解**：根据 App 类型和使用场景调整语气

### 专业术语处理

1. **技术术语**：统一使用行业标准译法
2. **产品术语**：保持品牌一致性，重要术语可不译
3. **UI 控件**：Button、Dialog 等标准译法统一
4. **错误提示**：清晰、友好、专业
5. **按钮文字**：行动导向，简洁有力

## 工作流程

### 模式A：全量/常规增量翻译

```
1. 目录扫描
   ↓
2. 基准语言识别（自动检测 zh-CN 或 en）
   ↓
3. 列出所有目标语言文件
   ↓
4. 差异分析（基准 vs 目标）
   ↓
5. 增量翻译（只翻译差异部分）
   ↓
6. 质量校验（术语、格式、长度）
   ↓
7. 更新目标语言文件
```

### 模式B：选中内容增量翻译（优先模式）

**如果检测到用户选中了部分内容或指定了 keys，优先使用此模式**

```
1. 识别用户选中的内容或指定的 keys
   ↓
2. 从基准语言中提取对应的 value
   ↓
3. 只翻译这些 keys（不扫描其他内容）
   ↓
4. 质量校验
   ↓
5. 精确更新到各目标语言（不改动其他内容）
```

> ⚡ **优先级说明**：当检测到用户有选中文本时，优先使用模式B，不进行全量扫描！

## 支持的文件格式

### 1. Flutter 项目 (.arb)

```
默认目录：lib/l10n/
格式：app_en.arb, app_zh.arb, ...
```

### 2. iOS 项目 (.strings)

```
默认目录：*.lproj/Localizable.strings
格式："key" = "value";
```

### 3. 前端通用项目

- JSON 格式：`src/locales/*.json`
- YAML 格式：`src/i18n/*.yaml` / `*.yml`

## 高级功能

### 1. 术语表自动记忆

- 记住项目中的专有名词
- 确保相同 key 在不同语言的一致性
- 建立项目专属术语库

### 2. 反模式检查

- ❌ 禁止逐字硬译
- ❌ 禁止过长的按钮文字
- ❌ 禁止文化敏感内容
- ❌ 禁止格式不一致

### 3. 翻译报告

- 显示本次翻译的 key 数量
- 列出新增和修改的内容
- 提示可能需要人工审核的条目

## 注意事项

⚠️ **首次使用**会进行全量翻译，后续默认为增量翻译
⚠️ **重要内容**建议人工审核，特别是专业术语和文化表达
⚠️ **建议备份**语言文件，以防意外情况
⚠️ **阿拉伯语**等 RTL 语言需要额外注意 UI 适配
